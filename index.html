What gets checked

Readability and accessibility

  • Text contrast against WCAG AA
  • Missing alt text, unlabeled buttons and form fields
  • Heading order and page landmarks
  • Tiny body text and undersized labels

Mobile

  • Pages that scroll sideways on a phone
  • Tap targets under 24px
  • Text pressed against the screen edge
  • Hero sections that push the call to action below the fold

The template look

  • Default fonts, purple-to-blue gradients, glow shadows
  • Pill chips above every headline, icon-tile feature grids
  • Cards inside cards, flat type hierarchy, uniform spacing
  • Buzzword copy and em-dash-heavy text

Launch basics

  • Mobile speed (LCP, layout shift, blocking scripts)
  • Share preview: title, description, OG image, favicon
  • Leftover default builder metadata
  • Console errors and failed requests on load

Questions

Do you need access to my code for the free audit?

No. The audit only loads your public pages in a browser and doesn't log in, submit forms or change anything.

How do you deliver the fixes?

If your project is synced to GitHub (Lovable, Bolt and v0 all support this), you get a pull request to review. Otherwise I send exact prompts and CSS for your builder and walk you through applying them.

Is this just an automated report?

The checks are automated, but I review every report before it's sent, and a person does the fixes. Some findings are judgment calls, and those are labelled as such.

Will the fix break my site?

Fixes come as a PR, so you can preview them before merging. The quick fix sticks to styling, metadata and markup, and doesn't change your app logic.
